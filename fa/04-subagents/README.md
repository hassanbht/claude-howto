# مرجع کامل Subagents

## مروری کلی

Subagents دستیارهای AI هستند که متخصص در انجام نوعی از وظایف هستند. آن‌ها زمینه ایزولته، پرامپت‌های خود و مجوزهای ابزار را دارند، برای تقسیم کارهای پیچیده به نقش‌های مختلف مناسب هستند.

## مزایای اصلی

- ایزولاسیون زمینه
- تقسیم telegraph استفاده شده
- برای اجرای موازی و تفویض مناسب است
- به تقسیم کارهای پیچیده کمک می‌کند

## موقعیت فایل‌ها

- سطح پروژه: `.claude/agents/`
- سطح کاربر: `~/.claude/agents/`

## پیکربندی

### قالب فایل

Subagent معمولاً یک فایل Markdown با frontmatter است.

```yaml
---
name: code-reviewer
description: بازبینی کیفیت کد و مشکلات امنیتی
tools: Read, Grep, Bash
---

# Code Reviewer
```

### فیلدهای پیکربندی

| فیلد | توضیحات |
|------|--------|
| `name` | نام subagent |
| `description` | چه زمانی باید فراخوانی شود |
| `tools` | ابزارهای مجاز |
| `model` | مشخص کردن مدل |
| `prompt` | پرامپت وظیفه |
| `context` | استراتژی زمینه |

### انتخاب‌های پیکربندی ابزار

- فقط-خواندن برای بازبینی
- محدود کردن Bash
- مجاز کردن مجموعه-tools قوی‌تر

### پیکربندی مبتنی بر CLI

همچنین می‌توانید از طریق خط فرمان یا فایل تنظیمات subagent تعریف کنید.


## Subagent‌های داخلی

Claude Code همراه با برخی نقش‌های رایج است، مثلاً:

- دستیار عمومی
- Planning agent
- Explore agent
- claude агент پیش‌فرض
- Statusline+مربوط به агент
- claude-code-guide агент

## مدیریت Subagents

### استفاده از دستور `/agents` (توصیه می‌شود)

> **نکته**: راهنمای تعاملی `/agents` در v2.1.198 حذف شد و از v2.1.281 `/agents` دیگر در منوی `/` یا `/help` نمایش داده نمی‌شود. لطفاً به Claude بگویید تا subagent بسازد یا مدیریت کند، یا مستقیماً فایل `.claude/agents/<name>.md` اضافه کنید.

```text
یک subagent برای بازبینیsecurity کد بساز.
```

Claude برای شما فایل `.claude/agents/<name>.md` را می‌نویسد، و frontmatter مناسب را (ابزارها، مدل، توضیح) انتخاب می‌کند. سپس می‌توانید آن فایل را دستی تنظیم کنید، یا به Claude بگویید آن را تغییر دهد.

### مدیریت مستقیم فایل

#### ایجاد subagent پروژه

```bash
mkdir -p .claude/agents
```

#### ایجاد subagent کاربر

```bash
mkdir -p ~/.claude/agents
```

## استفاده از Subagents

### تفویض خودکار

دستیار اصلی می‌تواند بر اساس توضیح وظیفه، کار را به subagent مناسب تفویض کند.

### فراخوانی صریح

همچنین می‌توانید به صراحت به Claude بگویید تا از یک subagent خاص استفاده کند.

### فراخوانی با `@`

در برخی سناریوها، می‌توانید با `@agent-name` به آن ارجاع دهید.

### آDasgent سطح جلسه

می‌توانید در کل peril.session از یک agent ثابت استفاده کنید.

### لیست agent‌های موجود

برای مشاهده subagent‌های پیکربندی شده، می‌توانید از Claude بپرسید، یا `.claude/agents/` و `~/.claude/agents/` را مرور کنید.


## Subagent‌های بازیابی

برخی subagentها می‌توانند ابتدا اجرا شوند، بعد بازیابی شوند، برای تسهیل وقتیcontinuity.

## زنجیره Subagents

در کارهای پیچیده می‌توانید چند subagent را به ترتیب همکاری کنید، مثلاً:

1. بازبینی کد
2. تولید تست
3. به‌روزرسانی مستندات

## حافظه پایدار Subagentها

Subagentها می‌توانند دامنه حافظه خود را داشته باشند، تا در هرکدام از وظایفشان یکپارچگی را حفظ کنند.

### دامنه حافظه

- سطح پروژه
- سطح کاربر
- سطح زیردایرکتوری

### نحوه عملکرد

Subagent در زمینه خود از حافظه مرتبط می‌خواند، و کاملاً با peril.session اصلی درهم نیست.

## Subagent‌های پس‌زمینه

### پیکربندی

برخی subagentها می‌توانند به عنوان وظیفه پس‌زمینه اجرا شوند، بدون مسدود کردن peril.session اصلی.

### شورت‌کت‌ها

در واسط‌هایی که پشتیبانی می‌کنند، می‌توانید از در میان‌برهای کلیدی برای مشاهده یا تغییر subagentهای پس‌زمینه استفاده کنید.

### بستن وظایف پس‌زمینه

اگر نمی‌خواهید وظیفه در پس‌زمینه اجرا شود، می‌توانید در تنظیمات آن را غیرفعال کنید.

## عزل worktree

### پیکربندی

می‌توانید یک worktree جداگانه به subagent تخصیص دهید.

### نحوه عملکرد

به این ترتیب وظایف مختلف وضعیت فایل‌ها را درهم نمی‌کنند.

## محدود کردن Subagent‌های قابل اجرا

می‌توانید به Claude اجازه بدهید فقط subagent‌های خاصی را spawn کند، تا ریسک کاهش یابد.

### مثال‌ها

- فقط اجازه به agent‌های بازبینی
- ممنوع بودن agent‌های اتوماسیون با ریسک بالا

## دستور CLI `claude agents`

`claude agents` **agent view** را باز می‌کند (v2.1.139+): لیست تمام‌صفحه Sessions پس‌زمینه grouping شده بر اساس وضعیت. این تعریف‌های subagent پیکربندی شده را لیست نمی‌کند؛ برای خواندن وضعیت peril.session به صورت اسکریپتی از `claude agents --json` استفاده کنید.

## Agent Teams (زمینی)

Teams agent حالت کار با هم Sync-el برای انجام یک وظیفه است، ایده‌آل برای کارهای پیچیده.

### Subagents در برابر Agent Teams

- Subagents روی تفویض تک وظیفه تمرکز دارند
- Agent teams روی همکاری چندنظری تمرکز دارند

### فعال‌سازی Agent Teams

از طریق تنظیمات ویژگی‌های experiment را فعال کنید.

### شروع تیم

حالت تیمی وظایف مختلف را تقسیم می‌کند.

### تخصیص و پیام وظیفه

دستیار اصلی مسئول تفکیک وظیفه و ارسال آن به subagent مربوطه است.

### فرآیند تایید برنامه‌ریزی

اگر فرآیند plan-مدیری است، تیم ابتدا برنامه را بررسی می‌کند و سپس اجرا می‌کند.

### رویدادهای胡ک تیمی

برخی胡کها می‌توانند در حین چرخه عمر تیم فعال شوند.

### بهترین شیوه‌ها

- نقش‌ها را مشخص کنید
- مراز وظیفه را مشخص کنید
- چندین agent نکنید که کار تکرارپذیر انجام دهند

### محدودیت‌ها

- ویژگی‌های experiment ممکن است تغییر کنند
- تیم‌های پیچیده به پیکربندی بیشتری نیاز دارند


## امنیت Subagent در پلاگین

subagent‌های توزیع شده در پلاگین باید به مجوزها، دامنه ابزار و شرایط مرز توجه ویژه‌ای داشته باشند.

## معماری

### معماری بلندمدت

دستیار اصلی، subagent، سیستم فایل و مجوزهای ابزار به’ensemble زنجیره اجرا را تشکیل می‌دهند.

### چرخه عمر

1. ایجاد
2. تفویض وظیفه
3. اجرا
4. بازگشت نتیجه
5. پایان یا بازیابی

## مدیریت زمینه

### نکات کلیدی

- زمینه زیرد minimal باشد
- هر subagent فقط به کارهای خود مسئولیت بپذیرد
- همه اطلاعات را در یک جا decisión نکنید

### ملاحظات عملکرد

بیش از حد بالا بودن سرعت را کاهش می‌دهد و درستی را پایین می‌آورد.

### رفتار کلیدی

subagent در زمینه ایزولته کار می‌کند، اما می‌تواند نتیجه را به peril.session اصلی بازگرداند.

## چه زمانی از Subagent استفاده کنیم

- وظیفه را می‌توان تفکیک کرد
- نیاز به ایزولاسیون زمینه
- نیاز به تقطيع واضح نقش‌ها
- نیاز به همکاری موازی

## بهترین شیوه‌ها

### اصول طراحی

- مسئولیت واحد
- توضیحات مشخص
- به حداقل رساندن مجوزهای ابزار

### بهترین شیوه‌ها برای System Prompt

- توضیحات وظیفه را مشخص بنویسید
- خیلی طولانی ننویسید
- فقط اطلاعات مورد نیاز برای انجام وظیفه را حفظ کنید

### استراتژی دسترسی به ابزار

- subagent بازبینیی فقط-خواندن
- subagent اجرا Ilende به程度 محدود حق نوشتن
- اقدامات با ریسک بالا باید تایید شوند

## راهنمای نصب

### روش ۱: استفاده از `/agents`

> **نکته**: راهنمای تعاملی `/agents` در v2.1.198 حذف شد و از v2.1.281 `/agents` دیگر در منوی `/` یا `/help` نمایش داده نمی‌شود. لطفاً به Claude بگویید تا subagent بسازد یا مدیریت کند، یا مستقیماً فایل `.claude/agents/<name>.md` اضافه کنید.

```text
یک subagent سطح پروژه بساز که تست‌ها را اجرا و خطاها را برطرف کند.
هر آن را به Bash، Read، Edit و Grep دسترسی بده.
```

Claue فایل `.claude/agents/<name>.md` را با frontmatter مناسب می‌نویسد. پس از بررسی فایل تولید شده، می‌توانید از آن استفاده کنید.

### روش ۲: کپی به پروژه

```bash
mkdir -p .claude/agents
cp 04-subagents/*.md .claude/agents/
```

### روش ۳: کپی به دایرکتوری کاربر

```bash
mkdir -p ~/.claude/agents
cp 04-subagents/*.md ~/.claude/agents/
```

### تأیید

- به Claude بگویید تا یک subagent بسازد، یا مستقیماً فایل `.claude/agents/<name>.md` اضافه کنید
- لیست دایرکتوری را بررسی کنید تا validated باشد که فایل‌ها در جای خود هستند: `ls .claude/agents/`
